:toc: macro

== Phase 2: Automation Interlingua

*Status*: Planned (new north star — see link:docs/decisions/0002-automation-interlingua-declarative-imperative.adoc[ADR-0002])

=== Objective

Give HAR the ability to translate between *declarative* control (describe the
desired routing state) and *imperative* control (the ordered dispatch it
already runs), then generalise that duality into a tool-neutral **interlingua**
that lets heterogeneous automation estates (Puppet, Salt, Terraform, Ansible)
hand off and resume across each other — joining up fragments rather than
replacing them. The interchange substrate is **A2ML**.

=== Framing

It is *an interlingua, whose schema is a meta-model of automation, carried on
A2ML, that doubles as an execution IR when HAR runs it natively.* The long-term
payoff is a lingua franca for automation control; the acute near-term problem
is HAR's own declarative/imperative capability, which must be proven standalone
first.

=== Core artefacts

[%autowidth]
|===
|Artefact |Description

|Automation meta-model
|Tool-neutral ontology: Resource, Effect, Dependency, State (desired/observed/realised), Owner, Provider, HandoffBoundary, Provenance

|A2ML interchange dialect
|New A2ML schema carrying the meta-model (distinct from A2ML's existing metadata/state-checkpoint role)

|Two-level IR
|High-level declarative effect/resource graph + low-level imperative plan; *lowering* = graph->plan, *lifting* = plan->graph

|Provenance & handoff engine
|Linear ownership (Ephapax) + per-resource lifecycle (proven-FSM) + convergence invariants (Idris2); handoff = linear ownership transfer with checkpoint
|===

==== 2C — Install & package-management domain (first concrete domain)

First resource domain beyond routing, captured as a **staged subsumption
ladder** — least-structured first, incumbents last (ordering owner-directed;
see link:docs/decisions/0003-install-domain-staged-subsumption-ladder.adoc[ADR-0003]).
Tier 1 may begin once the 2A meta-model skeleton exists; tiers 4–5 feed 2B's
config-management front-ends.

[%autowidth]
|===
|Tier |Scope |Status

|1 — Package-manager-less installs
|`curl \| sh` scripts, hand-placed tarballs, `make install`, binary drops — regularise into declarative resources with recorded footprint, integrity, derived uninstall/upgrade
|☐ Pending

|2 — Forge-release regularisation
|GitHub Releases assets, tag-pinned source installs, checksum/attestation verification — forge as de-facto registry, structured origin
|☐ Pending

|3 — Direct package-file installs
|`dpkg -i` / `rpm -i` of downloaded `.deb`/`.rpm` — map manifests, dependency declarations, scriptlets onto the meta-model
|☐ Pending

|4 — Secondary managers behind one interface
|apk, scoop, chocolatey — define the uniform `PackageProvider` interface (query/install/remove/upgrade/pin/verify + capability flags); retrofit tiers 1–3 as pseudo-providers
|☐ Pending

|5 — Core package managers
|winget, Homebrew, apt, dnf/yum — validate the interface against the richest incumbent semantics; closes the loop with 2B package resources
|☐ Pending
|===

*Flagship workload (tiers 1–2):* centralising the estate's **prover, solver,
and language-toolchain** installs (Idris2/Coq/Agda/Lean; Z3/CVC5 and SMT/SAT

entirely through tier-1/2 channels; toolchain managers are themselves
tier-4-like providers acquired via tier 1, forcing schema/interface
composition early.

==== Long-term — Lingua franca

Human-authored surface router language over the meta-model (A2ML-backed);
`N` front-ends + `M` back-ends replace `N x M` point translators. Replacement
of existing tools is an optional, emergent consequence — never a precondition.

=== Acceptance Criteria

* [ ] *(2A gate)* A declarative route topology lowers to a plan, executes, and
  lifts back to an equivalent declarative topology — round-tripping through
  A2ML, entirely within HAR, no external tool
* [ ] Ephapax linear types reject any double-apply of a resource across a handoff
* [ ] *(2B flagship)* A partially-realised Puppet catalog is imported, handed
  off via A2ML, and resumed as Salt states without double-application
* [ ] A Terraform (declarative) and an Ansible (imperative) source both import
  to the same IR and re-export losslessly for the covered subset
* [ ] Federation view detects an overlapping-ownership conflict between two tools
* [ ] *(2C tier-1 gate)* A `curl \| sh`-style install is captured as a
  declarative resource with recorded footprint, then uninstalled and
  reinstalled idempotently from that record alone
* [ ] *(2C interface gate)* One declarative "ensure installed" A2ML document is
  realised unmodified by a tier-1 pseudo-provider, apk, scoop, and chocolatey
* [ ] *(2C validation gate)* apt, dnf, Homebrew, and winget adapters fit the
  `PackageProvider` interface with no special cases leaking into the meta-model
* [ ] *(2C flagship workload)* a host's full prover/solver/language-toolchain
  set is captured as one declarative inventory (versions pinned, integrity
  recorded) and reproducibly reinstalled from it on a clean host
* [ ] *(2C D2 gate)* history/undo works uniformly through the provider
  interface — including undoing a tier-1 install from its recorded footprint,
  where no native front-end exists

== Phase 3: Advanced Routing

*Status*: Planned

=== Objective

Add intelligent routing capabilities — ML-based scoring, adaptive load balancing, circuit breakers, and multi-strategy composition. Reframed as strategy concerns *within* the execution backend that the Phase 2 IR lowers onto.

=== Deliverables

[%autowidth]
|===
|Component |Description

|ML-based route scoring
|Score routes by latency, reliability, and cost using learned weights

|Adaptive load balancing
|Distribute events across targets proportional to capacity

|Circuit breakers
|Halt routing to failing targets with exponential backoff recovery

|Multi-strategy composition
|Chain routing strategies (e.g. score → balance → circuit-break)

|Strategy hot-reload
|Swap routing strategies at runtime without restart
|===

=== Acceptance Criteria

* [ ] Route scoring produces consistent rankings
* [ ] Load balancer distributes within 5% of ideal proportions
* [ ] Circuit breaker trips after configurable failure threshold
* [ ] Strategies compose without ordering bugs

== Technical Decisions

=== Why These Technologies?

[cols="1,3"]
|===
|Decision |Rationale

|*Rust for core*
|Memory safety, zero-cost abstractions, excellent async ecosystem

|*Idris2 for ABI*
|Dependent types prove interface correctness at compile-time

|*Zig for FFI*
|Native C ABI compatibility, cross-compilation, zero runtime deps

|*Ephapax for ownership*
|Linear types guarantee exactly-once event delivery

|*proven-servers*
|Formally verified FSM lifecycle and queue dispatch

|*PanLL for monitoring*
|Panel-based dashboard with live data sources

|*Gleam for backend*
|BEAM reliability, functional purity, actor model

|*No Python/Node*
|Avoid dependency hell, prefer compiled languages
|===

=== Architecture Principles

1. *Pluggable* — Routing strategies are trait-based and hot-swappable
2. *Type-safe* — Idris2 ABI proofs, Rust type system, Ephapax linear types
3. *Observable* — Metrics, traces, and PanLL panels at every layer
4. *Resilient* — Circuit breakers, retries, graceful degradation
5. *Target-agnostic* — Router dispatches to any conforming target
6. *FOSS* — No proprietary dependencies
