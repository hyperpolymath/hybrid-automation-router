== Overview

The Hybrid Automation Router (HAR) is an intelligent routing layer that receives automation events from multiple sources (filesystem watchers, webhooks, queues, schedules) and routes them to the best automation target based on capabilities, tags, priorities, and configurable strategies. The v0.2.0 workspace provides 8 crates covering core routing, configuration management, event dispatch with retry and dead-letter handling, health checking with degradation tracking, and metrics collection with snapshots.

HAR is designed for **tight integration** with {url-rpa-elysium}[RPA Elysium] while remaining fully independent — either can be used standalone.

== RPA Elysium Integration

HAR and RPA Elysium share:

* **proven-fsm types** — same state machine vocabulary for workflow transitions
* **proven-queueconn** — HAR publishes tasks, rpa-elysium subscribes (guaranteed delivery)
* **Common event schema** — via Idris2 ABI definitions in `src/abi/`
* **PanLL panels** — monitoring dashboards in `panels/`

=== Using Both Together

[source,bash]
----
# Start rpa-elysium in the background (subscribes to queue)
rpa-fs run workflow.json &

# Route events through HAR
har route filesystem --target rpa-elysium
----

== Technology Stack

[cols="1,2"]
|===
|Layer |Technology

|*Core Engine* |Rust (8 crates: har-core, har-config, har-dispatch, har-health, har-metrics, har-router, har-cli)
|*Backend* |Gleam (BEAM — event bus, persistence)
|*ABI* |Idris2 (formal proofs, shared with rpa-elysium)
|*FFI* |Zig (C-compatible implementation)
|*Config* |Nickel (typed configuration)
|*Build* |Guix (reproducible)
|*Panels* |PanLL (monitoring dashboards)
|===

== Quick Start

[source,bash]
----
# Build
cargo build --workspace

# Run tests
cargo test --workspace

# Show registered targets
har targets

# Test routing a filesystem event
har route filesystem

# Test routing with a target hint
har route web --target web-auto
----

== Crate Structure

[cols="1,3"]
|===
|Crate |Purpose

|`har-core` |Core types: events, targets, routes, strategies
|`har-config` |Configuration loading and validation (JSON, file-based)
|`har-dispatch` |Event dispatch to automation targets with retry and dead-letter queues
|`har-health` |Health checking for targets with degradation tracking
|`har-metrics` |Metrics collection for routing decisions with snapshots
|`har-router` |Routing engine with pluggable strategies
|`har-cli` |Command-line interface for route management
|===

== Routing Strategies

[cols="1,3"]
|===
|Strategy |Description

|*Direct* |Target hint bypasses all rules
|*CapabilityMatch* |Match event category to target capabilities
|*TagMatch* |Tag-based routing rules
|*RoundRobin* |Rotate across matching targets
|*WeightedRandom* |Probabilistic selection by weight
|*LeastLoaded* |Send to least-busy target
|*Failover* |Primary with automatic fallback
|===
